# 派对策划剧本（四类典型场景）

每个剧本遵循同一骨架：需求收集 → 链路推进（每步确认）→ 策划案输出。链路细节见 `api_reference.md`。

## 场景 1：儿童生日会（最高频）

用户示例："下个月想给 5 岁女儿办个生日会，10 个小朋友左右，上海有推荐的吗？"

1. 收集：日期范围、人数（含大人）、预算、孩子性别/喜好。
2. `mall-points-products`，`catRuleIds="1>6>20,1>6>21"`（生日+主题）。推荐话术：按主题契合度排序（如迪士尼系列、海底小纵队、过家家派对），说明常规版/尊享版差异（价格与内容）。
3. 用户选定 spu 后按流程 A 走 城市→门店→日期→场次。上海→ `code=310100`。
4. 场次展示时提醒：周末上午场最抢手，余位少的标注"手慢"。
5. 下单确认时附赠 checklist：提前 15 分钟到店、蛋糕可否自带以门店答复为准、礼品由门店提供。
6. 收尾提示：可用 `query-my-coupons` 看生日月优惠；现场加餐可走流程 B 补一份到店点餐方案。

## 场景 2：公司团建 / 部门聚餐

用户示例："周五晚上团队 12 人聚餐，预算人均 60，找个有意思的地方。"

1. 收集：城市、具体周五日期、人数、是否需要活动环节。
2. 两条路并行推荐：
   - 有趣路线：`catRuleIds="1>6>25"`（品鉴会，如品虾会、尝新会、程序员节派对）或体验营 `1>6>22`，走流程 A。
   - 吃饱路线：流程 B，外送拼单（beType=2）或到店（beType=1）；公司对公报销场景提示企业团餐（beType=6，先 `query-meal-assistance`）。
3. 点餐组合：`query-meals` 后按"人数×1.2 份主食 + 人均 1 份小吃 + 共享饮品"配比出 2-3 套，`calculate-price` 比价，叠加 `auto-bind-coupons`。
4. 输出对比表：主题派对 vs 普通聚餐（价格、时长、氛围、含餐情况）。

## 场景 3：班级/社群聚会（学生党，价格敏感）

用户示例："社团 8 个人想聚一下，预算很紧，人均 30 以内。"

1. 先 `campaign-calendar` 找当月优惠活动与新品（蹭活动氛围）。
2. 预算优先：`mall-points-products` 全类目看积分兑换（`query-my-account` 查积分），有可用积分先抵扣。
3. 流程 B 到店自取（beType=1，无配送费），`query-store-coupons` + `calculate-price` 压到人均预算内。
4. 输出时列出"再省 X 元"的具体动作（换券/换餐品/拼套餐）。

## 场景 4：品鉴尝新会（潮人/吃货）

用户示例："最近麦当劳有什么新品品鉴活动？想带朋友去玩。"

1. `campaign-calendar` + `catRuleIds="1>6>25"` 双查：日历看宣传节点，商城看可预约场次。
2. 注意品鉴会多为限时商品（upTime/downTime 窄），过期立即剔除并说明。
3. 流程 A 走完整链路；下单前强调场次时间与限时活动规则。
4. 收尾：提示 `query-lottery-info`/`draw-lottery` 有无积分抽奖加餐。

## 通用话术原则

- 每次只推进一个决策点，选项不超过 5 个，超出的先给 Top 3。
- 价格一律带单位、场次带余位、日期带星期。
- 用户犹豫时主动给"我的推荐 + 一句话理由"，但决定权交回用户。
- 全程不索要 Token、密码；配置只指向环境变量占位符。
